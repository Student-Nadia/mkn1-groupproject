# ПС-3 CLI (fw-cli)

- **Язык:** Python 3
- **Пользователь ОС:** fw-cli
- **Требования:** FR-02, FR-30 – FR-38, FR-44
- **Команда:** Иванова, Мартыненко, Назмеева, Попов, Саитгареев (вместе с ПС-4)
- **Сокет:** `/run/fw/cli.sock` (0600)

## Модули

| Модуль | Назначение | Состояние |
|---|---|---|
| commands | таблица 7 ТЗ как данные: права, события, аварийный режим, подтверждение, аргументы | готов |
| parser | разбор «группа действие [аргументы]», кавычки, имя=значение; M14, M06 | готов |
| validation | проверка по `common/validation.json`; правило ↔ `policy.json` ПС-1; критерии выборки → payload ПС-2 | готов |
| formatter | таблицы с заголовком, строка страниц, тексты M-кодов; пароли не выводятся | готов |
| core | ядро управления (общее с web): `access_error` (M03, M10) готов; `execute` — заглушка | частично |
| session | сеанс, IP из `SSH_CONNECTION`; `login` / `ping` / `logout` — заглушки | частично |
| repl | приглашения, подтверждение y/n, help; `run` — заглушка | частично |

## Принимает

| Команда | Назначение | Источник |
|---|---|---|
| `—` | ПС-3 — клиент, входящих команд управления нет | — |

## Отправляет

- auth.login / logout / ping / check → ПС-5
- rule.replace (путь к подготовленному policy.json), rule.get, state.*, stats.get → ПС-1
- log.query.*, log.packets.clear → ПС-2; log.write.event (E50, E43, события команд) → ПС-2
- integrity.* → ПС-6
- if.*, route.*, time.*, sys.* → ОС (sudo, фиксированный список)

## Как устроено выполнение команды

1. `parser.parse(строка)` → `Command`: команда из таблицы, позиционные и именованные аргументы (M14 — нет такой команды, M06 — не те аргументы).
2. `core.access_error(spec, роль, аварийный_режим)`: M10, если команда недоступна в аварийном режиме; M03 и событие E50, если нужна роль rw. Роль хранится локально после входа (FR-37a), ПС-5 повторно не спрашивается.
3. `validation.check_command(cmd, интерфейсы, номера_правил)`: значения полей (M06).
4. Подтверждение для команд с `confirm`: только ответ `y` выполняет команду.
5. Выполнение через подсистемы. Правила: ядро держит рабочую копию политики, пишет временный `policy.json` (`validation.rule_to_filter`) и отправляет `rule.replace` с путём к нему. В файл `/etc/fw/policy.json` изменения попадают только по `config save` (FR-41a).

## Тесты

```bash
make test                                   # все unit-тесты, включая tests/unit/cli
python3 tests/stand/test_stand_codec.py     # заглушки подсистем (tests/stand)
```

`tests/unit/cli/test_shared.py` прогоняет общие сценарии `tests/shared/*.json` (шаги `do: command`). ПС-4 прогоняет те же сценарии и должна получать те же коды и поля.
